# Device QA: full pass on TV_API34 (release build)

- Date: 2026-10-11
- Device: emulator-5554, AVD TV_API34, Android 14 (API 34), 1920x1080, density 320 (software decode, so no performance conclusions)
- Build: `tools/tv.sh install release` (R8-minified `app-release.apk`, package `app.bolbol.tv`, installed over the logged-in app, login kept). Installed once, never rebuilt or reinstalled afterwards. Main has since moved on (rebrand to «مهرناز», package `app.mehrnaz.tv`, profile tab); this report covers the installed pre-rebrand build only, so the «درباره» page still says «بلبل تی‌وی».
- Screenshots: `shots/2026-10-11/qa-*.png` (not committed; only this file is).
- Driving: `tools/tv.sh key` / `adb input keyevent`. RTL: LEFT = next item in a row, RIGHT = back.

## R8 / crash findings

None. No `FATAL`, no `AndroidRuntime`, no `ClassNotFoundException`/`NoSuchMethodError`/serialization exception from `app.bolbol.tv` in the crash buffer or main log across the whole session. `tools/tv.sh logs 300 | grep -E "FATAL|AndroidRuntime|Exception"` was run after every flow.

R8 risk areas that were exercised and work in the minified build: Retrofit + kotlinx.serialization (home feed, details, search, browse, account/My List), Room (progress, Continue Watching, hide/remove, watched toggle), Coil (posters, backdrops, cast photos), Hilt, Media3 (720p H.264 plus the own subtitle engine), the LAN phone-remote server (QR panel).

Only noise: `W/MessageQueue: IllegalStateException: Handler (android.media.MediaCodec$EventHandler) sending message to a Handler on a dead thread`, printed 4 times each time the player is released. It is a warning raised inside the framework `MediaCodec` while the codec is torn down, not an app crash and not R8-related (observed at 17:08 and 17:36 player exits).

## Bugs

### QA-01 · major · feature/account · My List: Back from details puts focus on «خروج» (logout)

- Screen: «لیست من» (account screen), after returning from a card's details.
- Repro: Home, UP until the top bar, LEFT x2 to «لیست من», OK, DOWN (first card), RIGHT x2 (third card), OK, wait ~4 s, BACK.
- Expected: focus returns to the card that was opened (design-system §Focus rules: "Back returns focus to where the user came from").
- Actual: focus lands on the «خروج» button (white focused button, uiautomator focused bounds `[144,124][286,220]`, the card was `[819,324][1099,744]`). One accidental OK press then logs the user out.
- Screenshots: before `qa-09r-before-open.png`, after `qa-09s-after-back.png` (also `qa-09m-after-back-2s.png`).
- Suspect: `AccountScreen.kt` `requestFocusWhenAttached()` re-requests `logoutFocus` whenever the screen re-enters (`state.loaded && loggedIn`), overriding the saved grid focus.

### QA-02 · minor · feature/playback · Player Back order: panel needs two presses, overlay is skipped

- Screen: player.
- Repro A: play any episode (deep link `bolbol://play/624236/1/1`), MENU (settings panel opens), BACK once, wait 2 s: the panel is still open (`qa-05ca` panel, `qa-05cb` after 1 Back: still open). A second BACK closes the panel and shows the overlay (`qa-05cc`). Reproduced 5 out of 5 times (qa-05y/05z, 05ad/05ae, 05ah/05ai, 05bg, 05ca-05cc), with and without moving focus inside the panel first.
- Repro B: with the overlay visible (just after the panel closed), one BACK leaves the player straight away (`qa-05z` to `qa-05aa`), instead of hiding the overlay first.
- Expected (checklist, `PlayerScreen.kt` BackHandler): BACK closes the panel, then the overlay, then exits, one level per press.
- Actual: first BACK is swallowed while the panel is open; overlay level is skipped.
- Suspect: key handling between the panel's focus owner and `BackHandler` in `PlayerScreen.kt` / `PlayerChrome.kt` (panel and `closePanel()`, `overlayVisible` timing).

### QA-03 · major · core/data (sync) + feature/home / feature/details · Synced progress shows «تمام شد» in Continue Watching and no progress bars

- Screens: Home «ادامه تماشا»; series details episode list.
- Repro: open the app with the user's account (progress pulled from the website). Look at the «ادامه تماشا» row (qa-02d, qa-06e, qa-06k): «The Other Bennet Sister» «قسمت ۱ · تمام شد», «Gelin Takimi 2» «تمام شد», «Summertime 1955» «تمام شد», «The Office» «قسمت ۲ · تمام شد», «One Hundred Years of Solitude» «فصل ۲ · قسمت ۱ · تمام شد», and others. Open «Prison Break» (qa-04k): primary says «ادامه فصل ۱ قسمت ۲» but the episode 2 row has no progress bar and no «… مانده».
- Expected: the row holds only unfinished items (DAO filters `completed = 0`), each with a progress bar and «N دقیقه مانده». Items played on the device show correctly (One Piece LEGO: «قسمت ۱ · ۲۹ دقیقه مانده», qa-06a).
- Actual: entries that came from the site's watch-list render «تمام شد» (remaining <= 0) without a bar, so "finished" titles sit in «ادامه تماشا» and the user cannot see how much is left.
- Suspect (not confirmed, release build has no DB access): progress rows pulled by the sync are saved with `durationMs = 0` (unknown), so `remainingMs`/`fraction` become 0 while `completed` stays false. Check `core/data` sync mapping and `formatRemainingFa` / `WideCard` for the zero-duration case (show the saved position instead).

## Observations (not bugs)

- Movie playback (Baazigar 720p) took TTFF 27.6 s on the emulator (software decode); only a bare spinner shows meanwhile. Not a performance finding, but a message after ~10 s would help on slow CDNs.
- Series TTFF 3.1 s, no dropped frames and no rebuffering in the diagnostics box (`drop 0`, `rebuf 0`).
- Mic button opens the system chooser in English («Complete action using», Speech Services by Google / Google with «Just once» / «Always»); acceptable, it is system UI.
- The QR panel shows the LAN URL with a long token (`http://10.0.2.15:8859/?t=…`) in plain text; fine for a private TV, noted only.
- After seeking with 60 rapid RIGHT presses the position moved ~3 min, not 10 min (presses coalesce); fine, likely by design.
- The settings «پخش» section shows no default audio/quality chip selected (helper text explains auto-choice).
